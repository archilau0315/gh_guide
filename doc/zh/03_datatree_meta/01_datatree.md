# 3.1 数据树速查

> 数据树是 GH2（和 GH1）最核心也最容易让人崩溃的概念。这一节讲清楚三件事：**它是什么、怎么变、怎么看**。

---

## 数据树是什么

GH2 里所有流过组件的数据，不管是一个点还是一万条曲线，都被组织成**树形结构**：

```
数据树 = 多个分支 (Branch)
  每个分支 = 多个 item (Item)
    每个 item = 一个值（点、曲线、布尔、数字... 任何类型）
```

用路径表示法：

```
{0;2;4}
 │ │ └── 第 4 个 item
 │ └───── 第 2 个子分支
 └─────── 第 0 个顶层分支
```

**关键直觉**：分支 = 分组，item = 分组里的东西。路径 `{}` 就是这个数据的"地址"。

---

## 四个最常见的变形组件

这四个组件是日常 90% 的数据树操作，**每个写一个理解口诀**：

### Flatten — 拍平

**口诀**：**去层级，全进一碗**

```
输入:                   Flatten 后:
  {0}  →  [A, B]          {0}  →  [A, B, C, D, E, F]
  {1;0} →  [C]            （所有 item 进同一分支）
  {1;1} →  [D, E, F]
```

用在：**你不在乎分组，只想要所有数据一次性处理**（比如把所有点丢进 `List Length` 看总数）。

### Graft — 嫁接

**口诀**：**每个 item 外面再套一层**

```
输入:                   Graft 后:
  {0}  →  [A, B]          {0;0} →  [A]
  {1}  →  [C]             {0;1} →  [B]
                           {1;0} →  [C]
```

用在：**想让每个 item 独立处理，变成单独分支**。比如 Loft 需要每根路径单独成一组。

### Simplify — 简化

**口诀**：**去掉多余空层，层级不变**

```
输入:                   Simplify 后:
  {0}    →  [A, B]        {0}    →  [A, B]    （不变）
  {0;0}  →  [C]           {0}    →  [C]       （上一层只有这一枝 → 提升）
  {0;1;0} →  [D]          {0}    →  [D]       （同理，上两层都是单枝 → 全收上来）
```

用在：**数据树层级是别人搞出来的（比如 Cluster 多套了几层），你不想要**。

### Shift Paths — 移位

**口诀**：**整体 ±N，像数组索引搬家**

```
输入:                   Shift +1 后:
  {0}    →  [A]           {0;0}  →  [A]    （路径整体加一层）
  {1}    →  [B]           {1;0}  →  [B]

输入:                   Shift -1 后:
  {0;0}  →  [A]           {0}    →  [A]    （路径整体减一层）
  {1;2}  →  [B]           {2}    →  [B]    （顶层 1 被踢掉，剩 2 变顶层 0？不对，是 {1;2} → {0;2}？）
```

> 注意：Shift Paths 减层时如果顶层有多分支，会变成一个合并枝。移位不是重排，是挪层级。

---

## 四个组件的对照表

| 组件 | 作用 | 层级变化 | 分支数 | item 总数 | 典型用途 |
|---|---|---|---|---|---|
| `Flatten` | 所有 item 合并到第 0 枝 | 全部拍平成 1 层 | 1（除非设 Cross） | 不变 | 批量统计、不关心分组 |
| `Graft` | 每个 item 变成自己的分支 | 加 1 层 | = item 总数 | 不变 | 每个 item 独立处理 |
| `Simplify` | 去掉单枝的空层 | 去掉多余层 | 可能减少 | 不变 | Cluster 输出清层级 |
| `Shift Paths` | 层级整体 ±N | +1 或 -1 | 不变 | 不变 | 路径统一加前缀 |

## Path Mapper 语法（进阶）

`Path Mapper` 组件（Data → Tree → Path Mapper）的作用是**按规则重写路径**，比 Shift Paths 灵活得多。

语法格式：`{patternA} → {patternB}`

### 通配符

| 符号 | 含义 | 示例 |
|---|---|---|
| `{i}` | 顶层索引 | `{i}` |
| `{j}` | 第 2 层索引 | `{i;j}` |
| `{k}` | 第 3 层索引 | `{i;j;k}` |
| `{n}` | 所有层级 | `{n}` |
| `{N}` | 从最深层往前数 | `{i;N}` |
| `a` | 字面整数 | `{0;1}` |

### 常用规则

| 规则 | 效果 | 输入 → 输出 |
|---|---|---|
| `{i} → {0;i}` | 统一加一层"外壳" | `{0}` → `{0;0}`, `{1}` → `{0;1}` |
| `{i;j} → {j;i}` | 交换前两层 | `{0;5}` → `{5;0}` |
| `{i;j} → {j}` | 去掉顶层 | `{0;5}` → `{5}` |
| `{i;j;k} → {i;k;j}` | 交换后两层 | `{0;1;2}` → `{0;2;1}` |
| `{i} → {i % 4}` | 索引取模 | `{0}→{0}`, `{5}→{1}` |
| `{n}` | 所有路径原样通过 | — |

### 实战场景

**场景 1**：10×10 网格点，路径 `{0..9;0..9}`，想拆成单列 100 个，每个保留原来的行列索引做 Metadata。

```
Path Mapper: {i;j} → {0;i*10+j}
```

**场景 2**：两个数据树 A 和 B，A 有 5 枝每枝 3 个，B 有 5 枝每枝 3 个，想"横向合并"成 5 枝每枝 6 个。

```
A → Flatten → {0;0..14}
B → Shift Paths +1 → {1;0..14}
→ Wrap Paths → 合并
```

## 组件速查（数据树类）

| 组件 | 分类 | 作用 |
|---|---|---|
| `Flatten` | Data → Sets | 拍平 |
| `Graft` | Data → Sets | 嫁接加层 |
| `Simplify` | Data → Sets | 去多余层 |
| `Shift Paths` | Data → Tree | 层级 ±N |
| `Path Mapper` | Data → Tree | 按规则重写路径 |
| `Path Access` | Data → Tree | 按路径取特定枝 |
| `Tree Branch Count` | Data → Tree | 分支总数 |
| `Tree Item Count` | Data → Tree | item 总数 |
| `List Length` | Data → List | 每枝 item 数 |
| `Wrap Paths` | Data → Tree | 多数据树套一起 |
| `Unwrap Paths` | Data → Tree | 拆套 |
| `Sort Paths` | Data → Tree | 按路径排序 |
| `Cull Paths` | Data → Tree | 按条件剔除分支 |
| `Param Viewer` | Params → Util | 可视化数据树（截图） |
| `Tree Viewer Topology` | Data → Tree | 拓扑关系可视化 |

---

## 本章小结

- 数据树 = 分支（分组）+ item（值），路径 `{;}` 是地址
- 四个核心变形：**Flatten 拍平 / Graft 加层 / Simplify 去层 / Shift 移位**
- Path Mapper 是高级工具，`{i;j} → {j;i}` 这类规则比 Shift 灵活得多
- 不确定数据结构时先接一个 `Param Viewer` 看清楚，再决定用哪个变形组件
