# 3.2 输入重复策略（Input Repetition）

> **这是从 GH1 转 GH2 最容易撞墙的差异**。GH1 里你几乎不用想，GH2 里每个输入端口都有独立策略。

---

## 策略对照表

GH2 每个输入端口的**右侧参数面板**里都可以设置输入重复策略。默认值是 `item · required`——这也是最常见的踩坑起点。

| 策略 | 含义 | GH1 对应 | 什么时候用 |
|---|---|---|---|
| `none` | 严格匹配：输入枝数 = 组件期望数，对不上直接报错 | GH1 原生行为 | 一对一严格对应 |
| `item` | 按 item 数量对齐（分支数随最短枝） | GH1 默认 | 大多数几何操作 |
| `list` | 按 list 数量对齐（外层分支数） | 接近 GH1 默认 | 批量处理多组 |
| `repeat` | 重复最短枝到最长长度 | **GH1 没有** | 常量配批量 |
| `wrap` | 循环回绕（最短枝循环用） | **GH1 没有** | 周期性数据 |
| `longest` | 取最长枝，短的补 null | **GH1 没有** | 强制最大 |
| `shortest` | 取最短枝，长的截断 | **GH1 没有** | 安全优先 |

---

## 每个策略图解

假设组件有两个输入端口，A 和 B，数据树如下：

```
输入 A:    输入 B:
  {0} → [a1, a2, a3]      {0} → [b1, b2]
  {1} → [a4, a5]          {1} → [b3, b4, b5]
```

### `item` 策略（默认，最常用）

按最短枝的**item 数量**对齐。A 的第 0 枝 3 个 item，B 的第 0 枝只有 2 个 → 对齐到 2。

```
A 处理前:  {0} → [a1, a2, a3]    {1} → [a4, a5]
B 处理前:  {0} → [b1, b2]        {1} → [b3, b4, b5]

item 策略对齐后:
  A: {0} → [a1, a2]     (a3 被截断，因为 B 只有 2 个)
  B: {0} → [b1, b2]
  A: {1} → [a4, a5]     (5 和 3 对齐到 3，A 只有 2 个，差一个)
  B: {1} → [b3, b4, b5]
```

> **关键**：`item` 策略按 item 数对齐后，短的那一侧**自动 repeat**（但只 repeat 一次），长的那侧**截断**。

### `repeat` 策略（GH2 新能力）

把短枝**循环重复**到长枝的 item 数。这正是 GH1 没有的。

```
repeat 策略:
  A: {0} → [a1, a2, a3]
  B: {0} → [b1, b2, b1]   ← b1,b2 循环补到 3 个
  A: {1} → [a4, a5, a4]   ← a4,a5 循环补到 3 个
  B: {1} → [b3, b4, b5]
```

**典型场景**：一个滑块乘 100 个点——滑块的值会自动 repeat 100 次，不用手动 Flatten+Graft 再拼。

### `wrap` 策略（GH2 新能力）

和 repeat 类似，但是**整个分支做循环**。

```
wrap 策略:
  A: {0} → [a1, a2, a3, a1, a2, a3]   ← 循环用 A 自己的内容
  B: {0} → [b1, b2, b3, b1, b2, b3]   ← 同步循环 B
```

**典型场景**：周期性图案（比如六边形阵列的颜色循环）——一组颜色 wrap 到每一行上。

### `none` 策略

严格模式：两个输入的**分支数必须完全一致**，item 数也一致。否则报错。

```
none 策略:
  A 有 2 枝, B 有 2 枝 → OK
  A 有 3 枝, B 有 2 枝 → 报错
```

用在你**绝对确定数据结构**的场景（比如自己构造的数据树），防止被系统静默截断搞糊涂。

### `list` 策略

按**分支数**对齐，不管每个分支里 item 多少。

```
list 策略:
  A 有 2 枝, B 有 2 枝 → 对齐
  每枝内部的 item 各自保留
```

### `longest` / `shortest`

| 策略 | 取谁 | 短的怎么补 | 长的怎么处理 |
|---|---|---|---|
| `longest` | 最长那个 | 补 null（空值） | 保留原样 |
| `shortest` | 最短那个 | 不补 | 截断 |

**典型场景**：`longest` 配合后续的 `Cull Nulls` 一起用——把所有分支强制拉到同一长度，再统一过滤。

---

## 与 GH1 的行为差异

| 场景 | GH1 | GH2 默认 (`item`) | GH2 (`repeat`) |
|---|---|---|---|
| 常量乘数组 | 自动 repeat，OK | 自动 repeat，OK | OK（更灵活） |
| 两个数组 item 数不同 | 按最短枝 repeat | 截断长的 | 循环重复短的 |
| 两个数组分支数不同 | 对齐后 repeat | 对齐后 repeat | 对齐后 repeat |
| 想显式控制行为 | 得先手动调数据树 | 每个端口可独立设策略 | 同上但 7 种策略 |

**核心结论**：GH1 帮你隐式做了 repeat，你不容易察觉。GH2 把这个能力**搬到了明面上**，让你自己选——但代价是你得学会选。

---

## 怎么调策略

1. 选中组件
2. 右侧参数面板，找到端口面板（可能需要点 "Inputs" 展开）
3. 端口旁边有个小齿轮图标（⚙），点开
4. 弹出 `Input Repetition` 对话框
5. 选策略 + 是否 required
6. 确定

---

## 最常见的三个坑

### 坑 1：默认 `item · required` 导致截断

**现象**：组件输出的数据比输入少了一截，或者某些 item 被静默吃掉。

**原因**：`item` 策略按最短枝对齐，长的那端被截断。你没注意到，因为没有报错。

**解决**：改 `repeat` 或 `longest`，然后后面接 `Cull Nulls` 检查。

### 坑 2：改了策略忘了"为什么改"

**现象**：半年后重开文件，看到某个端口设了 `repeat` 但想不起来为什么，改回 `item` 后全错。

**解决**：右键组件 → Notes，写清楚"这里设 repeat 是因为 xyz 变量需要自动补值"。以后忘了翻 Notes 就好。

### 坑 3：一个组件多个端口策略不一致

**现象**：组件运行时有些端口对齐了，有些报错。

**原因**：每个端口独立策略，改的时候漏了某个。

**解决**：统一规则——几何端口 `item`，常量端口 `repeat`，严格端口 `none`。养成习惯：每次加新端口就先设策略。

---

## 本章小结

- GH2 把 GH1 隐式的 repeat 能力**显式化**，给出 7 种策略让你选
- **默认 `item · required`** 是最容易撞墙的（长的截断、短的自动 repeat 一次）
- 高频场景配高频策略：
  - 常量 × 批量 → `repeat`
  - 周期性数据 → `wrap`
  - 严格对齐 → `none`
  - 安全优先 → `shortest`
- 不确定用什么？先跑一遍 `item`，看输出对不对，不对再调
